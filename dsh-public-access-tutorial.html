方案选型

先想清楚「公网入口」到底是什么

很多人第一反应是「配个 Nginx 反向代理」。但Nginx 反代 ≠ 公网可访问：Nginx 只是在服务器本地把流量转发给 dsh，它自己没有公网 IP，外部流量根本到不了它。

缺的不是 Nginx，而是一台能被全网访问到的入口。服务器在局域网 / 内网又没有公网 IP 时，唯一免费可靠的办法是：

✅
用「隧道服务」当公网入口在 dsh 所在服务器上装一个隧道客户端（如 Cloudflare 的 cloudflared），让它主动连出去，隧道服务商会给你一个公网网址。服务器无需公网 IP。

最终架构

你的手机 / 任何电脑
→
公网网址
xxx.trycloudflare.com
→
内网服务器
cloudflared
→
Nginx 反代
127.0.0.1:8080
→
dsh web
127.0.0.1:3080

简单说：浏览器 → 公网网址 → 隧道 → Nginx（负责改请求头 + 登录验证） → dsh。

1

在服务器上配置 dsh

让 dsh 在服务器本地起来

dsh 的命令行通常自带 web 子命令，会启动 Web 界面并默认绑定 127.0.0.1:3080：

启动 dsh Web在服务器上执行
dsh web --no-open
# 不带 --no-open 会自动尝试打开浏览器（服务器上一般没意义）
# 默认监听 127.0.0.1:3080，可在配置里改 host/port

确认它能用：服务器本机访问一下端口。

curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3080
# 返回 200 即正常
⚠️
需要模型 API Keydsh 用大模型，要在配置里填好 DEEPSEEK_API_KEY（或通过 settings 配置），否则界面能开但没法对话。
2

SSH 隧道本地访问

最基础、只有自己能用的方式

服务器是内网，你在自己电脑上不能直接访问它。用 SSH 端口转发，把服务器上的 3080 映射到你电脑的 localhost:3080：

建立隧道在你本地电脑执行
ssh -L 3080:127.0.0.1:3080 用户名@服务器地址

然后本地浏览器打开 http://localhost:3080 就能用。

⚠️
局限只有建立这条 SSH 隧道的这台电脑能访问；换台电脑 / 用手机流量就不行了。这就是为什么需要下一步的公网方案。
3

公网访问 + 用户名密码

隧道 + Nginx + basic auth 三步走

3.1 安装 cloudflared 隧道公网入口

下载单文件可执行程序（按 CPU 架构选，这里以 x86_64 为例）：

下载
cd ~
curl -L -o cloudflared https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
chmod +x cloudflared

为了「关掉终端也继续跑」，放进 tmux 会话里（下面用会话名 deepseek）：

在 tmux 里启动隧道
tmux new-window -t deepseek -n tunnel "cd ~ && ./cloudflared tunnel --url http://localhost:8080"
# 启动后切到该窗口看网址：tmux a -t deepseek，按 Ctrl+B 再按 2

运行日志里会出现一行公网网址：

https://chips-first-vic-breath.trycloudflare.com
✅
到这里已经能访问了但直接用会踩到下面 4.2 的 403 问题，所以先看 3.2 把 Nginx 加上。

3.2 关键：加一层 Nginx 反代解决 403

dsh 对 /api 请求做了「浏览器信任围栏」：只认 Host 是本机（loopback）的请求，防止 DNS 重绑定攻击。隧道把公网域名当 Host 转发过去，dsh 就回 403。

解决办法：用 Nginx 在中间改写。它只绑定本机 8080，转发给 dsh 时把 Host 改成 localhost、并去掉浏览器的 Origin 头——dsh 就认为是本机请求了。这样公网网址怎么变都不用再动 dsh。

安装 Nginx + htpasswd 工具
sudo apt-get update
sudo apt-get install -y nginx apache2-utils
Nginx 配置/etc/nginx/conf.d/dsh-proxy.conf
server {
    listen 127.0.0.1:8080;
    server_name _;

    auth_basic "dsh access";
    auth_basic_user_file /etc/nginx/.htpasswd;

    location / {
        proxy_pass http://127.0.0.1:3080;
        # 关键：让 dsh 认为请求来自本机
        proxy_set_header Host localhost;
        proxy_set_header Origin "";
        proxy_set_header X-Real-IP $remote_addr;
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }
    # dsh 的 WebSocket 事件通道也要单独放行
    location ~ ^/api/events\.(mux|host)$ {
        proxy_pass http://127.0.0.1:3080;
        proxy_set_header Host localhost;
        proxy_set_header Origin "";
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}

启用并重载：

rm -f /etc/nginx/sites-enabled/default
nginx -t            # 语法检查
nginx               # 启动（或 service nginx start）

3.3 设置用户名密码强制登录

dsh 能执行命令、读写服务器文件，裸奔到公网非常危险。给它套一层 HTTP 基本认证，访问必须先输账号密码。

创建密码文件用户名 simon，密码自定
htpasswd -bc /etc/nginx/.htpasswd simon '你的密码'
nginx -s reload

-b 表示密码直接写在命令行，-c 表示新建文件。文件里存的是哈希，不含明文密码。

3.4 让隧道指向 Nginx打通

把 cloudflared 从直连 3080 改到 Nginx 的 8080：

tmux kill-window -t deepseek:tunnel
tmux new-window -t deepseek -n tunnel "cd ~ && ./cloudflared tunnel --url http://localhost:8080"

从日志拿到新网址，浏览器打开，输入 simon / 密码 即可从任何网络使用。

4

踩过的坑（重点）

这些才是真正花时间的部分
  1. 以为配 Nginx 就有公网访问——不对。内网没公网 IP，必须先有「隧道」这个公网入口。
  2. dsh 报 transport failure for /api/host.listDirectory: HTTP 403——这是最坑的一个。原因不是 403 本身，而是 dsh 的 Host 围栏：Host 头不是本机就拒绝，防 DNS 重绑定。隧道把公网域名当 Host 传过去，就被拒了。改 Nginx 把 Host 改成 localhost 即可。
  3. 只改 Host 还不够，Origin 也会拦——dsh 还会校验浏览器发的 Origin，若不等于 Host 也拒绝。所以 Nginx 里要把 Origin 也去掉（proxy_set_header Origin "";）。
  4. 高权限接口被单独锁死——settings.* / credentials.* / agentPreset.* / host.openPath 这些 dsh 默认只允许本机回环，任何远程都无法调用，这是 dsh 的安全设计，不要强行绕过。
  5. cloudflared 启动时报 QUIC 预检 hard_fail——吓人，但常是误报。它检测的节点和实际连接的节点可能不是同一个，以日志里是否出现 Registered tunnel connection 为准，出现了就是连上了。
  6. 快速隧道网址会变——免费、无账号的 trycloudflare 隧道每次重启都会换一个随机网址。好在：只要 cloudflared 一直跑着，网址就固定；想长期固定，换 ngrok 免费静态域名或买域名 + Cloudflare。
  7. WebSocket 连不上——dsh 界面的事件流走 /api/events.mux 和 /api/events.host，Nginx 必须转发 Upgrade / Connection 头（见 3.2 的第二个 location），否则页面卡在加载。
  8. 没有 htpasswd 命令——Debian/Ubuntu 默认没有，要装 apache2-utils：sudo apt-get install -y apache2-utils。
  9. 改完不生效——改 Nginx 配置要 nginx -t 检查、再 nginx -s reload；浏览器里若还看到旧的 403 页面，Ctrl+F5 强制刷新一次。
  10. 关终端进程就没了——用 tmux 跑隧道（或 Nginx 用 systemd/service 托管），否则断开 SSH 就断连。
5

日常维护与安全建议

用起来顺手、也不给自己挖坑

维护命令

想做什么命令
查看当前公网网址tmux capture-pane -p -t deepseek:tunnel 然后找 trycloudflare
重启隧道（会换网址）tmux kill-window -t deepseek:tunnel 再 tmux new-window -t deepseek -n tunnel "cd ~ && ./cloudflared tunnel --url http://localhost:8080"
改账号密码htpasswd -b /etc/nginx/.htpasswd simon '新密码' 然后 nginx -s reload
改用户名htpasswd -bc /etc/nginx/.htpasswd 新用户名 '密码' 然后 nginx -s reload
容器/机器重启后nginx 启动 Nginx；再按上面重启隧道
🔴
安全提醒dsh 能执行命令、访问文件、调用你的大模型 API。拿到网址又没设密码的人 = 能完全操控你的服务器。哪怕设了密码，也不要把这个公网网址+账号密码发给不信任的人；用隧道要选择熟习的来源，必要时加 IP 限制或改成短期内有效的隧道。
⚠️
「免费+无域名」的代价快速隧道网址会变、且无在线率保证，适合个人临时用。想要固定域名和更稳定，建议买一个便宜域名走 Cloudflare，或租一台小 VPS 自己搭入口。
6

一键命令速查表

按顺序复制即可完整搭建
# ============ 服务器上 ============

# 1. 预装 Nginx + htpasswd 工具
sudo apt-get update && sudo apt-get install -y nginx apache2-utils

# 2. 写 Nginx 反代配置（见 3.2），然后：
rm -f /etc/nginx/sites-enabled/default
nginx -t && nginx

# 3. 设置访问账号密码
htpasswd -bc /etc/nginx/.htpasswd simon '你的密码'
nginx -s reload

# 4. 装 cloudflared
cd ~
curl -L -o cloudflared https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
chmod +x cloudflared

# 5. 在 tmux 里跑隧道（指向 Nginx 8080）
tmux new-window -t deepseek -n tunnel "cd ~ && ./cloudflared tunnel --url http://localhost:8080"

# 6. 从日志取出网址
tmux capture-pane -p -t deepseek:tunnel | grep trycloudflare

# ============ 你本地电脑（可选，SSH 隧道调试用） ============
ssh -L 3080:127.0.0.1:3080 用户名@服务器地址   # 然后打开 http://localhost:3080
